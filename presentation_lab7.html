1 / 4 Lab 7 — Ship It

Aurora Policy Assistant

From RAG notebook to production service — with caching, streaming, tracing, a regression gate, and an evaluation report.

Aurora Policy Assistant answers questions about insurance policy documents using retrieval-augmented generation. It retrieves relevant passages from a corpus, generates a grounded answer citing specific sources, and refuses to answer when the documents lack sufficient information. Every claim is cited to a numbered source the user can expand and verify.

Request Pipeline

POST /ask → Cache check → Embed query → Retrieve top-k → Generate + cite → Validate → Response

API Endpoints

POST /ask — Grounded answer with citations, cost, trace ID
POST /ask/stream — SSE streaming (generate-then-stream for citation safety)
GET /health — Index size, model profile, cache stats, uptime
GET /metrics — Cost, latency percentiles, cache hit rate

Observability Stack

  • Traces: Every request writes JSONL spans via aip.tracing — name, duration, cost, parent ID. Answers "why did request X take 9 seconds?"
  • Dashboard: Streamlit page reading trace files — latency by stage, cumulative cost, error log, cache hit rate
  • Alert: p95 latency exceeding 6,000 ms SLO triggers a red banner — action: check provider status and index health
  • Error semantics: 422 validation, 429 budget/rate limit, 503 upstream outage with Retry-After
4 / 4 Boundaries & Next Steps

What It Is Not Safe For

  • Coverage decisions without human review 13 ranking failures mean the system can miss relevant policy terms. A customer relying solely on this could get an incomplete answer.
  • Time-sensitive information Answers from a static corpus snapshot. Policy amendments after the last index build are invisible — no staleness detection.
  • Numerical claims in RAG mode Agent mode uses compute_premium for arithmetic; RAG mode does not verify numbers against a calculator.
  • Adversarial inputs Lab 6 guards blocked 71% of red-team attacks. The remaining 29% could manipulate tool calls or extract system instructions.

What We Would Do Next

1
Cross-encoder reranker Expected +5–8% correctness. Addresses 13 of 14 failures directly — gold docs exist in top-30 but are buried below final_k. Cost: ~$0.001 additional per query (local, free).
2
Semantic cache with measured threshold Expected 30–50% latency reduction on repeated traffic. Must sweep to find the threshold where wrong answers start — preliminary estimate ~0.92, well below what most teams assume is safe.
3
Feedback-driven golden set expansion Thumbs-down button writes to a review queue. Confirmed failures become new golden-set entries. Without this, the golden set fossilises and the gate stops catching new failure modes.
